Start from a description

Describe the idea however you like. An agent proposes a title, id, acceptance commands and prose; everything lands in the fields below for you to change. Nothing is written until you press Save.

Contract

An improvement runs in that project's repository, against its existing code. It is only started once the parent has been accepted, and its acceptance commands are run in addition to the parent's - a change that breaks what already worked is not accepted.

Models

Which model each vendor uses for this spec. Leftmost is the CLI's own default — drag right for a larger one. Order comes from models.json at the Forge root; edit that file if the ranking is wrong or a new model appears.

Acceptance commands

Forge runs these itself and ignores what the agent claims. If none of them fail when the project is broken, nothing else in this pipeline works. A spec without one is refused.

Evidence

Files to keep and show in the report. Images render inline. Globs allowed.

Running it locally

How to start the built app, with {port} where the port goes. Forge picks the port on 127.0.0.1, starts it after the gate passes, probes it for security problems, and stops it again. Leave blank for a project with nothing to serve.

Deployment

Run only when you press Deploy on an accepted project, and only after the security check. The command uses a CLI you have installed and logged into yourself; Forge never logs in and never holds a credential. Leave the command blank for a project that is not deployed.

Ads

Ads inside the app. test builds labelled test slots; live uses your public ids, but only in a deploy — gates, tests and recordings always build test slots, so nothing Forge runs routinely makes an impression on your account. Ids are public identifiers (publisher id, ad unit id), never secrets.

Description

The prose handed to the agent, in three parts. Be specific about what "correct" means for the tricky parts — the commands above can only check what you thought to check. Ask for a better version of any one part and the model sees all three, so a change to the Goal or the Non-goals comes back with the Notes reconciled.
